# Transactions, Activity & Reports

Developer notes moved out of CLAUDE.md (Oct 2026). Read before changing this area; update when you change it.

## Category Selection
Both the assisted flow and classic form use the same `CategorySheet` (Cashew style): search field, type toggle (Expense/Income), then a 4-column icon grid of parent categories. Tapping a parent that has subcategories opens a subcategory step (back arrow returns); searching shows a flat grid of all matches. Never drop the search field.

## Add/Edit Form & Detail Header
The classic form opens with a Cashew header band (category-pastel colored): an inset pill type selector (Expense/Income/Transfer, sliding white indicator), a 64px category icon with an edit badge and the category name under it (tap → CategorySheet), and a 40pt amount on the right (tap → `showCalculatorSheet()`). The AppBar title states the type ("New expense", "Edit transfer"…). Title, date/time and note share one filled card with dividers; the item/transfer cards use the same filled surface (`sfv`, no shadow). With a single line, `LineCard(compact: true)` hides its category, amount and per-item note, and the account dropdown shows the name only (the currency badge beside it is the currency picker). Transfers have no amount row in the card — the band is the amount. Add item / Scan receipt / Gallery are one row of equal `_ActionChip` tiles. Title suggestions never repeat the text already typed. The save action is the shared `BottomActionBar` (Save & new | Save, equal width) whose label steps "Enter amount" → "Add transaction"/"Save"; the assisted flow uses the same bar ("Add another item" above, theme accent Save — not the type color). One hero amount size for the form band, detail band, assisted amount step and bill splitter total: `kHeroAmountSize` (40, `widgets/tx_ui.dart`). `transaction_detail_screen.dart` uses the same band (name under the icon, type under the amount) so view and edit match, and hides its "Line detail" card when the line only repeats the header's category and note. The calculator is a seamless key grid, LTR in every locale, shows the user's decimal separator, and disables Done at zero (except when clearing an existing value).

## One-screen add (Entry mode "One screen", Oct 2026)

`quick_add_screen.dart` (`QuickAddScreen`), the default entry mode (`entry_mode` = `'one'`; onboarding sets it, `_EntryModeRouter` and `entryModeProvider` fall back to it). It also edits and takes prefilled lines (duplicate, template, quick-add bar, envelope Spend) — `/add-transaction` always goes through `_EntryModeRouter`, which opens `QuickAddScreen.fromExtra(extra)` when `QuickAddScreen.canTake(extra)` (all lines on one account and one currency; transfers always). Lines spread over several accounts or currencies open the classic form; step by step only starts new ones. Mockup: claude.ai/artifact/Au7EykzKK3Be4P1dZH2L2S.
- **Layout** (fits 360×800 at 115 % text): header (close + Expense/Income/Transfer pill, `FittedBox` so it never overflows) → scrolling middle: amount (Bricolage 48, typed text via `formatCalcExpression`; mid-sum the expression shows above and the result big), chip "USD · Account" (account picker) and, when needed, the rate chip "1 USD = 89,500 LBP" (calculator, edited in the big-number direction) → title field "What was it for?" → recent suggestions → pills (category + date; the account lives in the chip under the amount, wallet icon + caret, so a long category name has room) → envelope / Ready-to-assign card. **Pinned** under it: the extras row (Note · Split · Receipt · Photo, icon over label, receipt count badge) and the keypad (LTR, long-press ⌫ clears) with Save & new (hidden at zero) + "Save $X" / "Move $X" (scaled down, never cut: "Save LBP 42,000,000"). On screens under 800 dp tall (Galaxy A02) keys are 40 dp and the extras 44 dp so category and date stay visible. The account sheet says "To account" for income.
- **Suggestions**: newest distinct titles (`visibleNote(note)` before " — ") of the same type, filtered by what's typed; a single-line one carries category, account and amount (applied when the currency matches). Picking one fills everything; the amount is `_prefilled` (first digit replaces it). If the user already typed an amount, it fills only the title and category — the typed amount and its account (currency) stay (an LBP 1,250,000 must not turn into $82.40 on Bank). Typing a title then leaving the field runs `lookupAutofillByTitle`; picking a category runs `lookupAutofill` (same Settings › Auto-fill rules as the other forms).
- **Envelope card**: `envelopeForCategory()` (`core/engine/envelope_for_category.dart`, pure — the same rules the engine uses for the debit; `envelope_for_category_test.dart` checks they agree) + `allocationsProvider` balances in the account's currency: "X envelope · $before → $after left" with a bar (left / this spending / used), "N days left · about $Y a day" until `budgetPeriodFor(...).end` for today's spending. Would overspend → red card "over by", **Cover from** chips: the fullest envelope that can cover the shortfall alone, Ready to assign when it has enough (`engine.moveMoney`, SnackBar), Other… (`showMoveMoneySheet(cover: true)`). No category → hint; no envelope → "isn't budgeted". Income → gold card Ready to assign before → after (`unallocatedProvider`). Transfer → From/To rows with balances before → after (`accountsWithBalanceProvider`; destination credited at the rate), swap button, "envelopes stay the same" note.
- **Save**: same paths as the assisted flow — `recordTransaction` with one `TxLine` (or `recordTransfer`), note = "title — note", receipts written after, `LastUsedService`, duplicate check (`confirmDuplicateTransaction`), foreign account needs a rate (fetched with `getRateWithCache`, else asks), "Saved" SnackBar from `envelopeAfterSave` with Cover when overspent. Discard guard via `PopScope` + `confirmDiscardTransaction`.
- **Split** (in the screen, mockup board 6): needs a total first (`quickSplitNeedsTotal`). The total stays; `_items` (`_Item`: category, keypad expression, kept line note) — the first item keeps the category and holds the rest (`_itemAmount(0)` = total − the others, labelled "The rest" when it has no envelope), each tap on Split / Add item carves a new one out and selects it. `_target` is what the keypad types into (0 = the total, via the `_active` getter/setter). Rows: category icon (tap → `_pickCategory(item:)`), envelope after the spending (items in one envelope add up; the envelope's name only when it differs from the category's), amount, × (amount returns to the first; one item left ends the split). Items over the total → red line + save blocked (`quickItemsOverTotal`). Saves one `TxLine` per item with an amount; no duplicate check. Suggestions/autofill leave category and amount alone while split. Switching to Transfer drops the split.
- **Edit** (`editTransactionId`): prefilled from `txFormArgs` (title/note split on " — ", date + time, one line → amount + category, several → items, stored rate kept — `_applyAccountDefaults` only fetches when `_rate` is null). `_loadEditState()` carries the receipts over and records what the saved version did (its ledger rows per envelope, its Ready-to-assign change, its account changes) so every "before" figure excludes it (`_envBalance`, `_oldUnallocated`, `_oldAccount`) — otherwise the edited amount counts twice. Save records the new one first, then `deleteTransaction(old)`; pops with the new id (Activity flash). No Save & new, no duplicate check. Discard guard compares `_signature()` with the opening state.

## Exchange Rate Input
Both forms have a swap button (↕) on the exchange rate field to toggle between "1 USD = X LBP" and "1 LBP = X USD". The `rateInverted` flag tracks direction; `exchangeRateToBase` is stored correctly regardless.

## Linked Transactions

Mixed-type items from the assisted flow (e.g., expense + income in one session) are split into separate transactions but linked via matching `note` + `createdAt` timestamp. The transaction detail screen queries for siblings and shows a "Related transactions" section of `TxTile` rows (`showBalance: false, showDate: true`) in one card, so a linked transaction looks the same as in Activity. For transactions with empty notes, the query additionally requires different `type` to avoid false positives.

## Spending Heatmap

`lib/shared/widgets/spending_heatmap.dart` — GitHub-style activity grid showing daily spending intensity. Green = net positive (income > expense), red = net negative, gray = no activity. Horizontal scroll, month labels, tooltips on tap. Data from `dailySpendingProvider` (SQL query grouped by day). Displayed in Reports Overview tab.

## Transaction Selection

Cashew-style: long-press a transaction to enter selection mode (there is no context menu). Tap rows to select/deselect; adjacent selected rows merge into one highlighted block, with an animated check circle. The selection bar replaces the header and shows count, Edit + Duplicate (exactly one selected) and Delete (with Undo). Edit (selection bar, swipe right, detail screen) and Duplicate open the form with `txFormArgs()` (`widgets/tx_form_args.dart`) — every line, rate and both transfer accounts; the edit form reloads the transaction's receipts from the DB so they carry over. Changing month clears the selection. Swipe gestures are disabled during selection mode. Rows are the shared `TxTile` widget (`lib/features/transactions/widgets/tx_tile.dart`), also used for the dashboard's recent transactions (`showBalance: false, showDate: true`).

## Activity Tab FAB

The + FAB on the Activity tab uses a custom `Material` + `InkWell` circle (not `FloatingActionButton`) so both `onTap` and `onLongPress` work reliably. Tap opens expense form directly (most common action). Long-press opens a type picker bottom sheet (expense/income/transfer, and a full-width **Split a bill** row → `/bill-splitter`, premium-gated). There is no separate split button over the list (removed Oct 2026: it covered row amounts and clashed with the add screen's own Split); only scroll-to-top stacks above the +. **Never wrap `FloatingActionButton` with `GestureDetector(onLongPress:)`** — the FAB's internal `InkWell` swallows the long-press gesture.

## Finding & Fixing Transactions

- Activity tab reads `transactionEntriesProvider` (all months) instead of the monthly provider while `_allMonths` (search text, date range, or a "See all" request); the "All months" chip clears the request.
- Filters: type, account (`_accountFilter`: header, destination or any line), category (also matches subcategories), date, amount (`parseLooseAmount`). Closed panel → `_buildActiveFilters()` chips (`AppChip` with ×; tapping one removes that filter) + Clear all; `_clearAllFilters()`. Type filters, the category-filter chip and the date fields (theme `InputDecorator`) follow the shared widgets. The empty, loading and error bodies sit in a scroll view (`_pullable`) so pull-to-refresh works on an empty month.
- **See all** (account detail, envelope detail): `activityFilterRequestProvider` (`core/providers/activity_filter_provider.dart`) → `MainScreen` switches to Activity → `TransactionsScreen._applyFilterRequest` (also on first build, since tabs are lazy).
- Selection ⋮: Select all (`_lastFiltered`), bulk category/account/date via `AllocationEngine.rewriteTransaction()` (re-records through `recordTransaction` + soft-deletes the old row, receipts carried; transfers: date only), Export CSV (`shareEntriesCsv`, one row per line in its own currency).
- Detail screen uses `transactionByIdProvider(id)` (single row, no running-balance replay). It shows the transaction as a paper receipt (`widgets/tx_receipt.dart` `TxReceipt`, Oct 2026): category icon (Hero `tx_<id>`), title (note before " — "), date · time, "Paid from / Into <account> ›" (transfer: "A → B"), dashed rules, one row per line (category, line note / other account, tabular amount, base conversion), TOTAL (plain amount; income keeps "+", long-press copies), the note after " — " in italics, a torn bottom edge (`_TornEdge` clipper) and a tilted one-ink stamp: expense → its envelope's balance now (`receiptEnvelope()`: the biggest categorised line's envelope via `envelopeForCategory`, in the line's currency — no entry there means 0, e.g. an LBP expense covered exactly; "over by" in red, else "left" in accent), income → Ready to assign, transfer → envelopes unchanged, upcoming → not paid yet, skipped. Under it: the receipt photos section, **Cover $X** (when that envelope is overspent, → `/allocations/<id>` cover) + **Duplicate**, a red **Delete**; ⋮ has Save as template and Delete. Envelope ledger rows, Reports drill-down rows and donut slices are tappable.

## Transaction Flash

When adding a transaction via the classic form, the new transaction ID is passed back via `context.pop(txId)`. The transactions screen highlights the matching tile with a 1.5-second accent glow fade-out using `AnimatedContainer`.

## Search Debounce

Transaction search uses a 400ms `Timer` debounce to avoid excessive `setState` calls during typing. Timer is properly disposed.

## Filter Persistence

Transaction type filter (All/Income/Expense/Transfer) is saved to SharedPreferences and restored on screen init. Persists across sessions.

## Duplicate Detection

Both the assisted flow and classic form check for duplicate transactions before saving. If a transaction with the same amount, category, and date already exists, a "Possible duplicate" dialog (`confirmDuplicateTransaction()` in `widgets/tx_ui.dart`, both forms) shows the matched transaction's title, amount, and date so the user can compare before confirming. Leaving a form with changes asks `confirmDiscardTransaction()` ("Keep editing" | red "Discard"); the bill splitter asks the same way with its own title. Skipped when editing existing transactions or for transfers.

## Activity List (BudgetSeal's own, Oct 2026)

The list answers "what did this do to my budget" (no longer Cashew's rows):
- **Month card** (`_MonthBudgetCard`, first sliver unless filters/all months): "<Month> budget" + "$X left"/"over by", gold 8 px bar, "Spent A of B budgeted · income C". Budgeted = targets of **spending** envelopes in the base currency; spent/income = the month's base-currency totals. A past month within budget collapses to "<Month> sealed" with `SealMark`. With filters, `_MonthlySummaryBar` (filtered totals) shows instead.
- **Day cards** (`_DayCard`): one card per day (sf, radius 16, card shadow, clips), `_DateHeaderTile` = Today/Yesterday/weekday in Bricolage 15 + date + day net (grey, follows `dateBannerTotal`), rows split by `bd` hairlines. No sticky headers. Scrolling down hides the title + month strip (`_headerHidden`, `AnimatedAlign` heightFactor so the strip keeps its scroll position; back on scroll up or near the top). The month strip has start/end padding (`_monthStripStartPad/EndPad`) so `_scrollMonthIntoView()` can center any month, including the current one (always last); `_setMonth()` re-centers after the frame. Rows are edge to edge (selection and swipe fills have no radius; the card clips).
- **`TxTile`**: 40 px rounded-square icon, 8 px vertical padding; title = note/payee, else category, else split categories, else type; second line = budget impact from `txEnvelopeImpactProvider` (`core/providers/budget_impact_provider.dart`): one watched query over the household's ledger replayed per envelope+currency in time order (consumption at its transaction's date, other rows at their own time) → "Envelope · **$X** left", red "over by $X" + Cover pill (only on the envelope's latest spending (`isLatest`) while `balanceNow` < 0, not in selection mode; opens `showMoveMoneySheet(cover: true)`), amber "Not budgeted" (expense with no consumption row), income → accent "→ Ready to assign" pill, transfer "Bank → Cash". End column: amount in Bricolage 16 tabular (expense = text color, income green "+", transfer grey), then "Account · balance after" (transfer: destination side), date instead when `showDate` (dashboard), "≈ base" for foreign lines, "No rate" pill. `balanceAccountId` (the Activity account filter) drops the name and shows that account's side of a transfer. `compact` hides the impact line; `showTime` appends the time.

## Faster Logging

- **Last used account**: `LastUsedService` (`core/services/last_used_service.dart`) stores the last account and transfer pair; both forms apply it to new transactions (`_applyAccountDefaults`). `_accountIsDefault` marks a defaulted account so category/title auto-fill may still replace it; picking an account by hand clears the flag. Prefilled lines without an account (a bill split's per-person lines) all get that default, but only line 0 takes the account's usual category; the others are in `_defaultedLines` and move with line 0 when an autofill (`_autofillAccount`) replaces its account.
- **Classic form**: Save & new (`_save(addAnother: true)` → `_resetForNext()`), Undo action on the Saved SnackBar for new transactions (`_undoSaveAction`), ⇅ swap on the transfer card, `DateQuickChip` (Today/Yesterday, shared with assisted), discard guard (`PopScope(canPop: false)` + `_signature()` compared at pop time — typing doesn't rebuild), prefilled foreign lines fetch a rate after the first frame.
- **Account pickers**: every account sheet in this feature (assisted account/destination, Activity account filter and bulk "Change account", bill splitter "From") is `showAccountPickerSheet()` (`widgets/tx_ui.dart`): theme sheet, `SheetTitle`, ListTile rows (wallet/airplane icon, name, balance in its currency, check on the current one), optional "All accounts" first row and "Add account" last row. The classic form keeps its inline account dropdown.
- **Receipts on the detail screen**: adding shows "Receipt attached"; removing asks "Remove this receipt?" first; both show a SnackBar on failure.
- **CategorySheet** takes `initialType` and `recentIds` (`recentCategoryIds()`); the assisted picker shows the same recents as chips.
- **Calculator**: a prefilled amount is highlighted (`_prefilled`) and replaced by the first digit. Mid-calculation ("12 + 5", not "12 +") a "= 17" line shows the running `_amount` under the expression; its 22 px line is always reserved so the keys don't jump.
- **Assisted**: `initialDate`/`initialTitle` params (quick-add title, viewed month), Enter on the title step continues, editable title row on the amount step, × removes the active item chip, the autofilled amount survives `_showAmountScreen()`.
- **Activity tab**: new transactions in a past month are dated its last day (`_newTxDate()`); quick add flashes the new row.
- **Notification/shortcut routing**: payloads are routes; `NotificationService.openRoute` (ValueNotifier) is set by taps (and cold-start launch details) and by `AppShortcutsService` (quick_actions: add transaction, fund envelopes, upcoming bills); `app.dart` pushes it.

## Auto-fill

`lib/core/providers/autofill_provider.dart` + `lib/core/services/autofill_service.dart`. When a category is selected, auto-fills fields from the last transaction with that category. Configurable in Settings > Appearance > Auto-fill: Account (default on), Title (default on), Amount (default off), Category per account (default off), Override existing values (default off). Works in both AF and classic form.

## Calendar

`features/transactions/calendar_screen.dart`, route `/calendar` (More › Money › Calendar and the Recurring screen's calendar button; it replaced the old bill calendar). A month grid (locale's first weekday, `_MonthGrid`): a day with transactions shows its net (income − spent) in the base currency (`_byDay`: same `isRealRate` rule as Activity's day totals) and is tinted by it: a pastel of the income color when positive ("+290"), of the expense color when negative ("-179"), `sfv` when even (transfers only) — the user's Transaction colors apply, today and later show bills due in the Upcoming blue (`_billsByDay`: every occurrence via `advanceRecurringDate` + `recurringAmountOn`, end date respected; the amount when one bill, dots when several — bills can be in other currencies). Today has an accent ring; the selected day an accent fill, or a 2 px accent outline when tinted (it keeps its color). Below: one day card (Activity's header + `TxTile` rows + `_BillRow`s with "Due in N days"; a bill row opens Upcoming bills). "Add on this day" (or double-tap a past day) opens the add form with `editDate`; future days can't take a transaction. Months: back freely, forward up to 12 months (bills only). Pull to refresh reloads the month and the bills; loading shows `SkeletonList`; a day with nothing is a quiet muted row inside the day card.

## Future Months

Transaction list caps month tabs to current month. No future months shown. Right arrow hidden at current month. Swipe-forward blocked. Year picker only shows up to current year.

## Reports Categories Tab

Cashew layout: `AppChip` toggle (Top spending / Top transactions) → donut (`_CategoryPie`, total in the center) → `_CategoryRow` entries (real `CategoryIcon`, amount with base-currency symbol, thin `BudgetProgress` share bar, "N% · N transactions", month-over-month change). Repeated colors get distinct shades via `_distinctColors()`. The hub's tab bar uses a pastel pill indicator.

## Reports Month Navigation

**Reports hub (Oct 2026).** The Reports tab (`ReportsHubScreen`) is `time/reports_home.dart` `ReportsHome`: `ReportSpanChips` (Month / 3 / 6 / 12 months / This year / Custom… → `reportSpanProvider`, `reportPeriodProvider` = a `ReportPeriod` of buckets from `reportBucketFor` — calendar months or budget periods per `reportsStartDayProvider`; `.previous` = the same length before), a story card (kept % / overspent / spent only, top category, spending vs the period before), Earned · Spent · Kept tiles with deltas, then the library in four groups. Rows open `/reports/view/:id` → `time/report_view.dart` `ReportView`: `budget` (`BudgetReport`: `envelopeHistoryProvider` = `envelopePeriodStats` per bucket; bars = spent with the planned amount (closing + spent) drawn behind, red when over; track record dots held / over (ring) / idle, last 12 buckets), `spending` (`SpendingReport`: stacked by the top 4 parent categories + Other, 2 px gaps; averages from the first month with spending; per-category sparkline + trend vs average), `places` (`PlacesReport`: titles before " — ", visits, weekday average per occurrence, busiest 3 hours, no-spend days + longest run), `biggest`, `money` (`MoneyReport`: grouped income/spent bars with kept under each month; net worth via `netWorthAt()` = today's base-currency account balances with later transactions undone), `accounts`, `currencies` (own currency, not converted), `subscriptions` (enabled recurring expenses → per month/year via `perMonth()`), `year` (`YearReport`, dark shareable card, `RepaintBoundary` → PNG). The old tabs live on as `LegacyReportPage` (`categories`, `insights`, `balance`, `overview`). One pass: `periodTotals()` (`time/report_period.dart`, base currency via `baseOf()` = `isRealRate`, transfers only in account flow). `test/features/reports_smoke_test.dart` builds every report at 360 dp / 115 % text in EN and AR (no overflow, no exception). `ReportScaffold` and the Year card pad the bottom by the system nav bar (3-button phones). Text inside a `FittedBox` under `IntrinsicHeight` (tiles, Year boxes) needs `maxLines: 1`, or the intrinsic pass measures it wrapped and the row grows tall. List rows put the amount beside the name (capped at 190 dp, scaled down) and the sub-line at full width, so LBP figures fit. Spending over time stacks only real categories (uncategorized money joins Other — both would be gray); Places leaves out goal and loan payments (`[obj:` notes). Balance sheet rows scale long figures. Income vs spending ignores months before the first money in or out (no "+0", no "every month above zero" from empty months).

All month reports (Overview, Categories, Insights) and Export report use `MonthNav` (`lib/features/reports/widgets/month_nav.dart`) with left/right arrows; the tabs add swipe (`_MonthSwipe`) and pull-to-refresh (`_RefreshableScroll`). Overview and Insights show an `EmptyState` ("Nothing recorded this month") for a month with no income or spending. Income / Expenses / Net is one widget, `IncomeExpenseSummary` (`reports/widgets/`), shared with Home's spending card; amounts and trend bars use `txColorsProvider`. The trend and daily-pace charts are both cards with the same empty card. Totals that can't mix currencies (velocity budget, recurring per month) count base-currency items only. The balance sheet groups by the account type code (`accountTypeIcon/Label` in `features/accounts/account_type.dart`). Its net worth hero splits the width 2:3 between the compare-date and today amounts, each in a `FittedBox` so big numbers shrink instead of overflowing; the change chip is hidden when the compare value is zero. The export report HTML is localized (and `dir=rtl` in Arabic). Users can browse any past month. The `reportStatsProvider.monthRange()` accepts an optional `from` parameter so the 6-month trend chart centers around the selected month. `_DailyPaceChart` accepts an optional `month` parameter — for past months it shows full-month data instead of stopping at `now.day`. The Insights tab filters spending velocity, biggest expense, and savings rate to the selected month using proper `monthStart`/`monthEnd` range checks.
